# Dynamic Image Auto-Tuning (`filter_speckle`, `min_thickness` & contour auto-selection)

Date: 2026-08-31 02:00

## Objective

Automatically evaluate and adapt vectorization parameters (`filter_speckle`, `min_thickness`, and `fit_tolerance`) dynamically for each input image based on its resolution, estimated noise floor (JPEG artifacts vs clean PNG), and thin line density, eliminating manual slider tweaking for clean vector outputs.

## Motivation & Architecture

Currently, fixed absolute defaults for `filter_speckle` (4) and `min_thickness` (1.0) work well for clean small images, but fail on:
1. **JPEG images with noise motes**: Fixed `filter_speckle` is too low on scaled canvas, leaving compression dots on skin.
2. **Thin ink drawings / Line art**: Fixed `min_thickness` can erase thin 1px face lines or glasses frames if set too high.
3. **Variable resolution**: A 300x300 image vs a 3000x3000 image require scaled speckle areas ($s^2$).

### Dynamic Evaluation Strategy

1. **Working-Scale Area Scaling**:
   Scale `filter_speckle` dynamically with the square of the working scale factor $s^2$:
   $$\text{filter\_speckle}_{\text{auto}} = \text{clamp}\left(4 \cdot s^2, 4, 64\right)$$
   where $s = \text{working\_scale} / 300$.

2. **Noise Floor Estimation**:
   Estimate high-frequency noise variance $\sigma_n^2$ in color-gradient analysis (e.g. Laplacian / gradient variance in low-contrast regions). For noisy JPEGs, scale $\text{filter\_speckle}$ up to $2.5\times$ to absorb compression ringing.

3. **Thin Feature & Line Art Protection**:
   Analyze edge topology (ribbon ratio $A / P$). If thin lines ($w \le 1.5\text{ px}$) make up more than $5\%$ of image boundaries (like line art / faces / glasses), dynamically clamp $\text{min\_thickness}_{\text{auto}} = 0.5$ to protect strokes.

4. **Web Application Auto Toggles**:
   Add `autoSpeckle` and `autoThickness` checkboxes in `web/views/IllustrationPanel.jsx` (enabled by default) so users get optimal results automatically while still retaining manual override sliders.
