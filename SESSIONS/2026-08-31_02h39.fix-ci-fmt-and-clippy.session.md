# Fix CI: rustfmt and clippy on the better-splines merge

Started 2026-08-31 02h39.

## Context & Objectives

Run [33350179727](https://github.com/jgermade/vektro/actions/runs/33350179727) of the `Build`
workflow failed on `main` at `075f225` ("Feat/better splines (#3)"), 21 seconds in. The failure is
the very first check of the job, `cargo fmt --check`, which exits 1 and aborts the run before
clippy, the tests, the wasm build or the web bundle ever get to say anything.

The four files reported by rustfmt all come from that merge:

- `src/centerline.rs`: trailing whitespace on a blank line inside `extract_centerline`, and a
  hand-wrapped `vec!` literal in `test_extract_centerline` that rustfmt wants one element per line.
- `src/cluster.rs`: the `auto_speckle` expression is over the line width and has to break at the
  method chain.
- `src/fit/spline.rs`: the `cut_idx` `if`/`else` fits on one line.
- `src/lib.rs`: `pub mod centerline;` was inserted before `pub mod boundary;`, splitting it from the
  `#[cfg(feature = "illustration")]` attribute above it and breaking the alphabetical order rustfmt
  keeps for the module block.

Because the run stopped at the first step, whatever comes after it was untested. The objective is
not just to make `cargo fmt --check` pass but to walk the whole `build.yml` job locally, so the next
push is green all the way through rather than red one step later.

---

## 1. Formatting

- Run `cargo fmt` and take its output as-is on the four files above. No hand edits: the point of the
  check is that the file matches what the tool writes.

## 2. Clippy

- `cargo clippy --all-targets -- -D warnings` is the next step in CI and had never run on this code.
  It reports `needless_range_loop` in `src/centerline.rs:52`: the inner loop over `num_samples..n`
  uses `j` only to index `points`.
- Rewrite it as `for &p2 in &points[num_samples..]`. `n` is `points.len()`, so the slice is the same
  range, and the outer loop keeps its index because `i` is also used in `(i + num_samples) % n`.

## 3. Walk the rest of the job

Everything downstream of the two failing steps, in the order `build.yml` runs it, to confirm nothing
else in the merge is broken:

- `scripts/corpus.sh`, then `cargo test` and `cargo test --release` with `REQUIRE_CORPUS=1`.
- `wasm-pack build --release --target web --out-dir web/pkg --out-name vektro -- --no-default-features --features wasm,illustration`,
  then `git diff --exit-code -- web/pkg/vektro.d.ts` and `node scripts/web-smoke.mjs`.
- `npm ci`, `npm run lint` and `npm run build` in `web/`.

## Non-goals

The six `no-unused-vars` warnings oxlint prints for `web/views/Preview.jsx` (`copied`, `source`,
`progress`, `decoding`, `ms`, `handleShare`) are left alone. `npm run lint` exits 0, so they do not
fail CI, and they are leftovers of the preview rework that belong to whoever finishes it.
