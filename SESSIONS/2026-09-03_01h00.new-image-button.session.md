# A button to load another image

Date: 2026-09-03 01h00

## Request

A "new image" button, to the right of `nav.tabs` on desktop and between `main`
and the footer on mobile.

## Why it is needed

With the workspace open, `DropZone` is `hidden`, so once an image is loaded the
only ways to change it are dragging a file onto the window or pasting. Both are
listeners on `window` with nothing on screen saying so. The `h1` resets the view
(`converter.reset()`), but that is a different thing and its only affordance is a
`title`.

## Shape

- `web/components/NewImage.jsx` — the button plus its own hidden `<input
  type="file">`. It does **not** reuse `DropZone`'s input: that one carries
  `id="file"`, and two elements with the same id in the document is a bug
  waiting to happen.
- It hands the file to `App.handleFileSelect`, which already puts up
  `ConfirmModal` when there is an image loaded. So "new image" asks before
  throwing away what is on screen, for free.
- Rendered **twice**, once per position, with CSS showing whichever the viewport
  calls for. A single element cannot be both inside the header row and between
  `main` and `footer` without a portal, and the hidden copy is `display: none`,
  so it is out of the accessibility tree and there is no duplicate control.
- Only when an image is loaded. With no image the drop zone is right there,
  filling the screen and saying the same thing.

Breakpoint: 860 px, which is where the workspace already switches from two
columns to one and what `App.jsx` itself calls mobile.

The label goes through `t()` like the rest of the chrome, with `new_image` added
to `web/messages/es.yml` and `en.yml`.

Noted while looking: the repository has **two** message directories, `messages/`
at the root and `web/messages/`. Only the second one is imported
(`web/services/i18n.js` reads `../messages/*.yml`, relative to `web/services/`).
The root copy is behind — it has no `share_svg` — so it looks like a leftover.
Not touched; flagged.

## Walkthrough

- `web/components/NewImage.jsx` (new) — button plus its own hidden file input.
- `web/views/Header.jsx` — `Tabs` is now wrapped in `.tabs-row` with the button
  next to it; the component takes `active` and `onFile`.
- `web/views/App.jsx` — passes them down, and renders the second copy between
  `</main>` and `<Footer />`.
- `web/assets/style.css` — `.tabs-row` (which takes over the `margin-top` the
  `.tabs` block used to carry), `.new-image` in both placements, and the two
  media queries at 860 px that pick one.
- `web/messages/es.yml`, `web/messages/en.yml` — `new_image`.

Checked on both viewports with a throwaway probe page mounted under `web/`
(deleted afterwards), because a headless browser cannot drive a file input and
the button only shows with an image loaded:

- 1200 px wide: to the right of the tab group, aligned to the right edge of the
  content column.
- 520 px wide: centred between the workspace and the footer, top copy gone.
